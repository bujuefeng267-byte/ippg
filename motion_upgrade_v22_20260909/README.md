# rPPG V2.2：像素采样与短缺帧处理

目标是在运动时保留细小的颜色脉动，并在有足够观测数据的前提下减少短暂断续。该版本属于现有数据上的开发与回归实验，具体效果见 `优化结果与研究路线.md` 和 `evaluation/`。

## 使用

在 WSL 项目 `/home/fengbujue/项目/rppg识别` 中，安装后运行：

```bash
./run_motion_v22.sh /absolute/path/video.avi --output /absolute/path/new_result
```

默认每个 ROI 使用固定两端各 10% 的截尾均值，短缺帧上限 0.10 秒。单独验证的连续性选项为：

```bash
./run_motion_v22.sh /absolute/path/video.avi --output /absolute/path/new_result_gap15 --max-gap 0.15
```

用 `--rgb-aggregation median` 可恢复中位数采样，供工程消融；它仍包含 V2.2 的时长取整修复，不能冒充旧 V2.1 的逐字节结果。输出目录必须尚不存在。旧的 `run_motion_v21.sh` 仍可独立运行。

## 改动

1. ROI 内原先对每通道取像素中位数。8 位图像的中位数受整数/半整数格点限制，容易抹掉小幅颜色扰动。新采样先沿每通道去掉最高及最低各 `floor(0.10×N)` 个合法像素，再以 float64 取均值，保留跨像素平均产生的细小变化。
2. 合法像素仍要求三个 RGB 通道有限且严格在 20–245 之间，仍至少需要 25 个像素。ROI 几何、人脸检测与光流桥接、采样质量定义没有放宽。
3. 短缺帧上限换算为 `floor(gap_seconds×fps)` 帧，避免向上四舍五入超出指定时长。0.15 秒在约 30 fps 视频中最多补 4 个缺失帧。只补两端有真实样本的完整短缺口，不补长缺口，也不向片头或片尾外推。
4. 插值继续单独记录。心率窗口仍为 10 秒、约每秒一次，要求至少 90% 真实观测；原有滤波边界、ROI 共识与波形来源核验继续生效。

本轮没有根据 Polar 心率修改搜索频带、候选选择、融合权重或 DP 代价。POS、CHROM、ROI 融合及最终波形读出的数值阈值保持固定。新方法的结果不能预先保证优于旧版，逐片结果均保留。

## 输出

- `frame_trace.csv/json`：逐帧检测、ROI 颜色与质量、实际采样方式及缓存身份。
- `pos/chrom/fusion_waveform.csv`：原程序波形、观测和插值标记。
- `pos/chrom/fusion_heart_rate.csv`：局部频谱峰、离线 DP 心率、接受/拒绝状态。
- `fusion_proposals.csv`、`fusion_diagnostics.csv`：候选频率与实际融合来源。
- `summary.json`：运行配置、源码哈希、输出覆盖率及限制。

`accepted` 是程序是否输出结果，不是准确率或置信概率。波形覆盖率也不等于波形形态的准确率。零相位滤波、重叠融合、DP 都使用离线数据；本版本没有声称达到实时零延迟。

## 验证与文献

`run_validation_v22.py` 在原审计工作目录中运行六个采集来源和两种固定设置，推理不接收参考。`evaluate_v22.py` 再按原协议评估同步 UBFC、合成 72 bpm 及估计同步的 data1；没有参考的视频只评价输出和连续性。Kaggle 截短片与运动视频转码版不重复计数。

现有全部片段都曾用于观察或开发，不能同时称为独立训练集和测试集。最新论文核查及后续模型路线见 `literature.md`；本轮截尾均值是工程修复，不是对这些论文整套方法的复现。
