# 保留方案代码发布（2026-09-17）

本次同步已验证的 V28 连续波形＋V32 独立窗口心率入口、必要依赖与合成测试，保留既有 V26 和固定 POS 对照。算法参数、质量门槛和已冻结的推理代码未修改。

## 同一批14段录像的对照

| 方法 | MAE/bpm | ±5 bpm 内比例 | HR输出覆盖率 |
|---|---:|---:|---:|
| V26完整谐波重放 |37.86|20.24%|86.11%|
| V28 |34.24|18.99%|86.40%|
| V28连续波形＋V32窗口心率 |33.05|19.33%|86.40%|
| POS6 |31.83|27.43%|81.77%|

所有版本使用同一组691个计划窗口，其中688窗参考有效。MAE与±5比例按各分支有输出且参考有效的窗口计算，覆盖率按全部计划窗口计算。不同分支输出集合不完全相同。上述数据为反复使用的开发录像，原参考时间对齐未经硬件同步验证，不能宣称未知视频上的最佳性能。

保留方案相对V28的输出掩码不变，data5的MAE由19.44降至4.93，其余13段心率不变，原本正确窗口损伤为0。V26在data5为3.66；POS6在data8为4.00，因此这里的保留方案不是逐视频最优解。data6的保留方案误差仍约26.00 bpm，运动误判尚未解决。

[逐视频指标](retained_case_metrics_20260917.csv)。该CSV仅包含汇总指标，不含原始参考生理记录、人脸像素或逐帧视频内容。

## 为什么没有加入最近的新补偿

两种新RGB运动补偿在14组视频上虽略降整体MAE，却降低±5准确比例，并损伤原正确窗口。此前统一选择/跨视频学习选择也未通过采用检查。它们没有进入本次保留入口；本地冻结实验继续保留用于研究复现。

## 输出定义

从仓库根目录执行：

```bash
./run_retained_hr.sh --video /absolute/path/video.mp4 --out results/new_run
```

- `result_summary.json`：实际心率与波形文件路径、来源、校验和。
- `window_hr/heart_rate.csv`：固定10秒窗、1秒步长的心率；拒绝窗口保持缺失。
- `window_hr/windows_manifest.csv` / `window_hr/window_waveforms/`：每个心率对应的实测波形。
- `continuous_v28/waveform.csv`：新视频模式下原V28连续波形。缓存复用时保留在原目录。

没有把独立窗口拼成新的连续PPG，也没有声称PPG形态或SNR提高。全部流程仍为离线处理。

## 校验与依赖

Python依赖沿用根目录 `requirements.txt`。V32复用已发布V31的输入校验、CDF和保护组件，并验证冻结源码哈希；不要单独改动这些文件后绕过校验。POS的六块测量/投影依赖位于 `motion_dis_hybrid_v2_20260915`，作者来源和许可见其 `THIRD_PARTY_NOTICES.md`。该目录仅同步必要测量、POS共享内核和相关测试，没有启用DIS融合路由。

发布检查在仅包含Git已跟踪代码及本次明确文件清单的异地目录执行；测试记录见 [发布核验](retained_release_validation_20260917.json)。旧模块中的实验状态字段保留为其原冻结定义，顶层 `result_summary.json` 说明本次保留组合的实际输出。
