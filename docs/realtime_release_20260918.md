# 实时 rPPG 优化发布（2026-09-18）

新增 `run_realtime.sh` 实时入口，输入相机画面、输出同一测量窗口的 rPPG/BVP 波形和心率。默认使用 `fast`，保留原 R1 对照及 `motion` / `guarded` 两种可选实验；V28/V32 离线入口保留。

## 本次改变

- 对 POS 小窗口计算进行向量化，保持原数值行为。
- 浏览器持续捕获，只保留最新待发画面；网络请求完成即发送最新帧，避免额外等待一个摄像头刷新周期。
- 开启 HTTP/1.1 连接复用；默认保持 JPEG 98，增加 RGBA 无损颜色选项。根据 Windows → WSL 实测，RGBA 大包传输不足以维持同样帧率，因此未设为默认。
- 修复启动失败误停其他页面会话、停止后旧回调进入新会话及重复上传等生命周期问题。
- 保留真实时间戳、缺失掩码和实际输出延迟；不通过补零或复用旧心率提高表面覆盖率。

安装与运行见[实时版说明](../realtime_rppg_v2_20260918/README.md)。

## 固定 14 组开发视频对照

固定 691 个原始计划窗口，其中 688 个参考有效。预测先冻结、后读取参考评分；无逐视频参数或参考心率参与推理。MAE 和 ±5 bpm 比例只对有输出且参考有效的窗口计算，心率覆盖率对全部 691 个计划窗口计算。

| 方案 | MAE ↓ / bpm | ±5 bpm 比例 ↑ | 心率覆盖率 ↑ | ±5 bpm 窗数 |
|---|---:|---:|---:|---:|
| 原实时 R1 | 38.726 | 14.936% | 79.884% | 82 |
| `fast` 默认 | 38.726 | 14.936% | 79.884% | 82 |
| POS + CHROM 对照，未启用 | 36.998 | 14.513% | 82.200% | 82 |
| POS 重叠归一对照，未启用 | 36.090 | 14.464% | 81.476% | 81 |
| `motion` 实验 | 35.532 | 16.865% | 73.082% | 85 |
| `guarded` 实验 | 38.236 | 16.098% | 76.556% | 85 |
| 离线 V32 对照 | 33.049 | 19.328% | 86.397% | 115 |

`fast` 全部 690 个已发布事件与 R1 数值等价，波形最大绝对差为 0。准确率未变，优化的是计算与送帧效率。

`motion` 对 data5、data6 的 MAE 有明显收益，但后 8 组从 41.981 升到 48.015 bpm，整体覆盖也下降。`guarded` 28 次替换全部通过固定规则审计，改善集中于 data5；共同窗口 MAE 只改善 0.503 bpm，后 8 组反而增加 1.321 bpm。其覆盖少 23 个有效输出、少 2 个原正确窗，都来自录制末尾没有等到额外 2 秒输入。因此两者均未替换默认。

## 性能和验证边界

| 检查 | 结果 | 范围 |
|---|---|---|
| 同进程交替后端计时 | 中位 95.46 → 35.97 ms；逐窗速度比中位 2.64 倍 | 3 组缓存前 18 秒、各 2 轮、排除首窗，共 42 对；不含视频前端和网络 |
| WSL 内实时节奏回放 | 29.89 fps；第 10.03 s 首次有效输出 | 18 秒预录片段、RGBA、解码缩放在计时外；不是 Windows 摄像头实测 |
| Windows → WSL JPEG 98 | 连接复用前约 25.45 fps，后约 28.59 fps | 各 30 帧，重复同一预录帧；含真实前端，不含浏览器编码 |
| Windows → WSL RGBA | 复用后约 18.85 fps | 同上，未设为默认 |
| 浏览器调度模拟 | 33 ms 捕获的新帧在 35 ms 上一上传结束时即发送 | 确定性 Node VM 测试，不能当作实体摄像头延迟 |

本地原发布验证为 44 项 Python 测试及 13 项浏览器脚本模拟测试通过；GitHub 版本另在不含私有数据的源码快照中通过新版 44 项、原版 30 项 Python 测试，以及 13 项浏览器模拟测试。新下载运行只需仓库代码、依赖和用户自己的视频输入。

本批视频已反复用于开发，参考时钟是历史估计，并非硬件同步。能输出心率不代表已测准：一次短回放中仍有从约 101–102 跳到 184–185 bpm 的错误频率风险。实体摄像头的同步精度、独立受试者及设备泛化尚未验证。
