## 可以采用的对齐口径

- 沿用冻结方案：以 AVI 内部 ZIP 原始 Unix 修改时间近似录像结束，减实际解码帧数 / 精确 fps；这是条件对齐，非硬件同步。禁止将参考和视频各自起点归零，或用预测误差寻找偏移。
- 全报 −5、−2、−1、0、1、2、5 秒敏感性，不选最优。10 秒窗 / 约 1 秒步长按同一参考计算，拒绝窗口仍留在 R5 分母。
- data2 文件名暗示启动 16:21:46.381；mtime 减时长得到 16:21:46.5667131，差约 +0.186 秒，仅是独立的间接支持。
- data4 avih 帧数 10702 与 strh 长度 10693 相差 9 帧；必须以实际解码确认后再冻结时长。本审计只读头信息，不擅自决定哪项正确。data4 参考会话比视频长约 3 分钟，不可用参考终点替代视频终点。
- 所有 events 仅为采集软件连接、开始/结束事件；没有视频帧与参考时钟的明确对应。

## 完整性与时间字段

- 18 条流的样本索引连续、选择的时间轴严格递增、HR/PPG/ACC 数值均有限；小文件完整读到尾并由 ZIP CRC 自动验证，摘要核心字段与独立复算一致。
- 全部 HR 的 device_time_ns / device_frame_time_ns / rr_ms 为空；使用 host_utc_ns（整数纳秒）和 hr_bpm。其约 1 Hz 到达时间不是已校准的心搏时间。
- PPG 配置 55 Hz，时间戳重建后的端点率约 54.75–54.77 Hz；ACC 配置 52 Hz，实际端点率约 53.21–53.23 Hz。应保留原逐样本 device_time_ns，不按配置采样率重建新时钟。
- PPG/ACC 的 host 时间按批次重复属预期，不能去重成一条生理样本。device_time_ns 由采集器根据设备帧终点插值/回推；它与 host 到达时间的差不能直接解释成视频延迟。
- 各组均出现启动时一次连接失败、重试后一次成功连接；已记录数据段内未见断连事件或索引缺口。
- data1 与此前记录的三份原参考逐字节相同，视频长度 / CRC / 流头一致；它是重复分析同一来源。
