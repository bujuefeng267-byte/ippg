# data1 原始 Polar PPG / ACC 参考可靠性诊断

原始接触 PPG 的最大谱峰与 Polar 通知心率明显不一致；同时，PPG 与加速度在这些频率上高度相干。这支持“原始光学记录包含较强的共同机械扰动成分”这一解释，**不能据此判定通知心率错误，也不能把约 94 bpm 或约 188 bpm 的一半改作真值**。本审计不替换主参考、不调整 rPPG 代码、不搜索时间偏移。

## 时间字段与方法

读取 `meta.json`、`events.csv`、`polar_ppg.csv`、`polar_acc.csv`、`polar_hr.csv`。PPG/ACC 的 `device_time_ns` 已由采集库表示为 Unix ns，逐点时刻由批次端点插值或按名义率重建；`device_frame_time_ns` 是该批最新样本时刻，`host_utc_ns` 是整批到达时刻。没有把重复的批次主机时间当成逐点采样时间。

本次保留原始 device Unix 轴；HR 保留通知的 host UTC 轴，统一减去冻结视频起点 **1788939171166718500 ns，即 UTC 07:32:51.166718500（北京时间约15:32:51）** 作数值计算。没有将各流首样本分别归零，没有用生理信号拟合 lag。原视频起点仍是存档修改时间减时长的估计，不是硬件同步。主机接收时间减设备批端点，PPG 中位数 0.998 s、范围 0.842–1.249 s；ACC 中位数 1.026 s、范围 0.825–1.234 s。这混合传输/处理延迟和潜在时钟偏移，本审计没有擅自将其扣除；通知的内部生理平均延迟也未知。

取原有 `pos_heart_rate.csv` 的全部 42 个时间中心，与是否 accepted 无关，中心±5 s 为窗口。依记录时间插值到同一个 50 Hz 网格；超过原始中位间隔 3 倍的缺口不桥接。每条 PPG、ACC x/y/z 及加速度模长分别线性去趋势、Hann 加窗、NFFT=8192 周期图，**只在固定 0.7–3.5 Hz 内取最大谱峰**，不折半，不挑最接近参考的峰或通道。频率×60 只是便于比较的“每分钟频率”，ACC 峰不是心率。相干性使用 4 s Hann 子窗、50%重叠的 Welch 幅值平方相干性；每个10秒窗仅4个子段，所以仅作描述，不作为显著性或因果证明。零填充不增加10秒窗的信息分辨率。

## 记录质量与总体结果

PPG 4640 点/121批，ACC 4497点/81批；逐样本时间严格递增，sample_index 连续，信号均有限，队列丢弃记录为0。未见成功连接后的流内断连。PPG/ACC 的端点推算采样率分别54.745/53.218 Hz，而配置值为55/52 Hz，因此实际计算依记录时刻而非直接套名义采样率。软件重建时刻下的连续性不能证明硬件绝无丢样。HR共91条，没有可用RR或设备端HR时间戳。

第一窗三条原始PPG在约3.04 Hz处具有共同峰，并与ACC高度相干；第二窗PPG2的主峰落在约1.56 Hz，仍与ACC相干。因此“多个光学通道一致”或“某通道落在相机约94 bpm附近”都不足以确认真实脉率。约94与188的倍频关系是可见线索，但仅凭本记录不能确定步频、具体运动类型或心搏基频。

可以确认的是：原始接触PPG的主导频率没有独立复核通知HR，且带有与机械信号相关的强周期成分。不能确认的是：Polar内部算法是否已抑制该成分、通知HR是否准确、相机方法是否因同一物理源锁频。后者需要可信同步的ECG/逐搏参考或额外实验。主报告应继续称为“相对于用户指定Polar通知HR、在估计同步条件下的指标”，避免将本诊断用于挑选更有利真值。
