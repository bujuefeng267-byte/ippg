# V32：独立窗口心率与统一运动风险检查

V32 以完成的 V28 输出为输入，独立生成 CDF 候选，然后为每个十秒窗口保存实际采用的波形，并从该文件计算心率。它用于验证局部候选，窗口步长和原质量门槛不变。

```bash
./run_motion_v32_experimental.sh \
  --v28-output results/已完成的V28输出 \
  --out results/新的V32输出
```

旧批量 V28 目录没有自身跟踪缓存时，额外提供 `--trace-cache /完整路径/frame_trace.csv`。必须同时存在同名 JSON，并且缓存与原 V28 结果的哈希绑定一致。输出目录必须尚不存在。入口不接受参考心率，不修改输入，也不填补原本缺失的心率。

## 两种波形的含义

- `window_waveforms/window_XXXX.csv`：对应一个十秒窗口的实际测量片段。相邻窗口可能选用不同来源，因此同一时刻在不同窗口中可有不同波形值。这些片段没有被拼成一条连续 PPG。
- `windows_manifest.csv`：每窗的时间范围、来源、文件路径和 SHA256。通过它可找到每个心率使用的波形。
- `heart_rate.csv`：完整窗口计划、有效性及心率，包含波形来源。无效心率保持缺失。
- `waveform.csv`：原 V28 连续波形的原样副本，仅供上下文查看。V32 替换窗口的心率来自窗口文件，不能声称它们都由这条连续波形得到。
- `proposal_evidence.csv`、`routing_decisions.csv`、`guard_history.json`、`preservation_audit.json`：候选证据、实际选择、撤回原因和检查结果。

## 固定实验

批量实验包含 `window_only`（只改变窗口组织方式的诊断消融）和 `motion_guard`（统一运动否决的主方案）。公开的单次 CLI 固定使用主方案。

主方案要求新候选的直接运动风险可用、小于 0.50，且不高于原候选风险。所有最终可选的新频率都必须通过原始信号支持和运动检查。多个区域一致不自动覆盖运动否决；未知运动信息不被当作低风险。

所有心率从重新读取的窗口实测信号检查。未替换窗口保留 V28 的频率状态也须有实际频谱支持。原质量门槛、缺失处理及大跳撤回规则继续生效。

## 评价边界

六段已有视频是反复检查过的开发数据，参考时间对齐仍是估计。评价保持原 309 个十秒窗口，同时报告误差、准确比例、覆盖率、原成功窗口损伤及大跳。只有心率参考时，不能证明 PPG 波形形态或 SNR 提升。

当前推荐的连续 PPG 入口仍是 V28。即使独立窗口心率指标有所改善，也需要单独说明产品含义；不能直接把 V32 当作更好的单条连续波形算法。
