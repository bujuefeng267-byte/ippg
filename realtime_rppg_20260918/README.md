# 原实时 R1 对照

当前默认与安装方法见 [实时优化版](../realtime_rppg_v2_20260918/README.md)。本目录保留原 R1 数值和界面，用于对照。

这是独立的实时实验入口。保留原来的 V28/V32 离线入口。实时版本仅使用已经收到的帧，约积累 10 秒后开始尝试输出，此后每秒更新一次；质量不足时仍可能没有有效心率。

## 在这台电脑上启动

1. 在已配置依赖的仓库根目录运行 `bash run_realtime_v1.sh`，保持服务窗口打开。
2. 在电脑 Chrome / Edge 打开 <http://127.0.0.1:8765>。
3. 点击“开启摄像头”，允许摄像头权限。约 10 秒后观察波形和心率。
4. 点击“停止并保存结果”。页面会显示结果目录。

WSL 中也可运行：

```bash
bash run_realtime_v1.sh
```

默认接口仅限本机，不需要把摄像头转接进 WSL。浏览器把摄像头画面发送给本机服务。不同端口可用 `--port 8766`。若提示端口被占用，检查是否已有服务运行，直接打开已有页面。

建议稳定 30 fps，实际输入尽量保持 20–30 fps；页面显示真正送达分析的帧率。默认图像宽度最多 960 像素，请让面部足够大、额头和两侧脸颊可见。30 Hz 内部重采样不会增加真实帧数。宽度缩小、JPEG 传输和实时窗口都会影响结果，不能视作原离线算法的完全等价版本。

## 输出是什么

- **PPG/BVP 曲线**：皮肤颜色提取出的相对幅值信号，不是根据心率生成的正弦曲线，也不代表接触式 PPG 的绝对幅值或已验证的波形形态。
- **心率**：从同一个波形窗口读取，范围 42–210 bpm。横轴对应窗口结束时间；数值概括此前 10 秒，中心时间为结束时间减 5 秒。
- **缺失**：无可靠区域信号时留空，不补零，不用上一次心率冒充新的结果。输入暂停时隐藏旧心率。

波形每秒刷新为最近 10 秒的独立窗口；滤波仅在已收到的缓冲中进行。同一个历史时刻在不同窗口中的波形可能略有不同。每次已保存的窗口和心率不会再改写，因此这些重叠窗口不能直接首尾拼成一条严格逐样本因果的连续波形。

结果在项目 `results/realtime/会话时间/`：

| 文件 | 内容 |
|---|---|
| `heart_rate.csv` | 每次估计的心率、窗口范围、状态、计算时间、缺失原因 |
| `ppg_windows.csv` | 每个窗口的波形样本，包含窗口编号、采样时间、有效性；缺失幅值为空 |
| `window_00000.json` 等 | 精确波形及其心率、候选、质量和来源信息 |
| `frame_trace.csv` | 逐帧时间戳、区域 RGB、人脸与跟踪诊断 |
| `session.json` | 会话参数与运行摘要 |

默认不保存摄像头画面。服务只有一个活动会话，重新开始前先停止旧会话。

## 视频流及文件回放

```bash
.venv/bin/python realtime_rppg_20260918/run_source.py \
  --source 'rtsp://摄像头地址' --out results/realtime/my_stream

.venv/bin/python realtime_rppg_20260918/run_source.py \
  --source '/完整路径/视频.mp4' --realtime --out results/realtime/my_replay
```

输出目录必须是新目录。`camera:0` 只适用于当前运行 Python 的系统能够直接访问的摄像头；Windows 摄像头优先用上面的浏览器入口。RTSP/直接摄像头使用容量为 1 的最新帧缓冲，防止程序内部积压；设备和网络自身延迟仍需现场测量。读帧到达时间不等于已验证的硬件曝光时间。

文件回放使用声明帧率的 CFR 时钟，不能直接用于有可变帧率、丢帧或错误时间戳的精度结论。去掉 `--realtime` 可测计算吞吐，但吞吐不等于真实摄像头到屏幕的延迟。

## 与旧版的关系及验证边界

复用原皮肤采样、像素跟踪、局部异常筛选、失败回退、POS 投影、区域融合和候选评分。实时版另做实际时间戳处理、过去窗口和只向前的频率跟踪。原 V28/V32 的整段优化依赖后续数据，不能原封不动作为实时输出。

验证摘要见[发布说明](../docs/realtime_release_20260918.md)。软件链路能运行，不代表运动中的心率精度问题已经解决；缓存评估、录制视频回放和真实摄像头测试需要分别看待。
