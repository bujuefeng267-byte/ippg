# V28：分析一个新视频

这个入口保留 V25 的原始融合波形作为回退，并使用 V26 的谐波候选处理。只有原心率频率本身具备足够的直接运动证据，且满足原 V26 的其它条件，才允许混入候选实测分量。所有视频使用相同规则；没有输入参考心率或按视频选择方案的接口。

在项目的 WSL 环境运行（输出目录必须尚不存在）：

```bash
cd /home/fengbujue/项目/rppg识别
.venv/bin/python motion_upgrade_v28_20260912/analyze_video_v28.py \
  --video /完整路径/新视频.mp4 \
  --out results/新视频_v28
```

如果已有完全一致的 V25 锚定跟踪缓存，可以添加：

```bash
  --trace-cache /完整路径/frame_trace.csv
```

缓存必须包含同名 JSON 元数据。程序核对视频 SHA256、原前端代码、参数、CSV 校验和与均匀时间轴，并完整解码视频核实实际帧数和帧率。旧缓存缺少视频 SHA256 时，必须保留原先邻近的 `inputs_manifest.json` 来证明它对应的输入视频；当前视频的校验和不能补造旧缓存的历史绑定。只读取清单中的视频路径、字节数和校验和，不读取参考文件。

## 输入要求

- 本地 OpenCV 能完整解码、分辨率不变的常帧率视频。代码按 `frame / fps` 建立时间轴，尚未处理可变帧率的逐帧时间戳。
- 帧率必须大于 7 fps，以支持固定的 42–210 bpm 搜索范围；这只是频率采样下限，不是推荐拍摄帧率或准确率保证。
- 不设固定分辨率门槛。人脸和皮肤区域需要在画面中清楚可见；更高分辨率本身不能保证运动状态下可靠提取。
- 心率使用 10 秒窗口、约 1 秒步长。视频不足 10 秒时仍保存逐帧缺失波形和空心率表，不补造结果。
- 原始视频不被修改。目标结果目录已存在时直接拒绝覆盖。

## 输出文件

| 文件 | 含义 |
|---|---|
| `ppg_and_hr.png` | 最终测量波形与心率折线图；没有输出的位置留空 |
| `waveform.csv` | 每帧时间、测量信号 `base`、有限采样覆盖 `covered`、观察/插值来源及候选权重 |
| `heart_rate.csv` | 完整窗口计划、`ridge_bpm`、`accepted`、失败状态和频谱证据；无效心率为 NaN |
| `routing_decisions.csv` | 每个窗口的替换资格及理由，含直接运动证据 |
| `v25_fallback/` | 从本次同一前端数据生成的 V25 波形、心率、区域信号、融合诊断 |
| `v26_harmonic_candidate/` | V26 候选实测分量、候选频率、区域证据及独立波形读出心率 |
| `frame_trace.csv`、`frame_trace.json` | 完整时间轴、RGB/运动数据与缓存绑定 |
| `manifest.json`、`summary.json` | 输入及代码校验和、完整解码帧数、可用率和运行记录 |

最终心率在保存并重新读取 `waveform.csv` 后独立估计，没有直接拼接 V25/V26 的心率数值。候选频率也不等于最终心率。

最终波形保留 V25 的有限值/缺失位置；混合所涉及的真实贡献源会决定 `observed` 和 `interpolated` 标记。相邻 10 秒窗口的平滑叠加会影响本窗口没有获得替换资格的部分样本，不能把 `route_eligible=False` 解读成该窗口全部样本都没有变化。

候选来自实测信号的自适应窄带处理，没有用目标频率生成正弦波。但包含窄带分量的波形仍不能证明完整 PPG 形态得到了恢复。这个入口不读取参考数据，覆盖率只代表输出可用性，不能据此报告准确率；准确率需要另外与同步参考测量比较。
