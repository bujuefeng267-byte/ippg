# V2.4：保留像素跟踪、局部筛选和失败回退的改进实验

本轮依据近期光流引导区域选择、rPPG质量共识研究，以及V2.3的独立合成反例进行修改。目标是与原V2.2在相同设置下比较心率误差和输出覆盖率；结果未出前不预填提升结论。它是现有传统算法管线的独立改进，不是复现论文的神经网络或最先进精度声明。

## 保留的三个步骤

1. 前后向LK跟踪同一组皮肤小块，逐帧更新种子。
2. 根据小块相对共同颜色变化的偏差筛选局部异常，保持原阈值。
3. 跟踪点不足时回退原ROI颜色变化；缺失仍为缺失，缺口后重置。

V2.3的像素跟踪实现保持原样，新增处理读取它的配对颜色增量。检测可用率和观察／插值标记不因新版本而抬高。

## 修改

**bounded_tracking**：在log颜色域累积配对变化，用0.15Hz四阶因果Butterworth低通对“原始log颜色−积分log颜色”作校正。它限制慢性积分漂移，比一阶锚定更强地隔离原色中的高频运动。每个ROI的有效连续段拥有独立积分和滤波状态。四阶校正仍有启动延迟和频率泄漏，不保证抑制全部运动；整个后端仍为离线处理。

**guarded_fusion**：原V2.2采样和上述有界跟踪采样各自通过原有多ROI/POS/CHROM质量门槛。两个分支不增加独立ROI数量。只有实际贡献的至少两个ROI在窗口内真实跟踪比例≥60%、重置比例≤5%时，跟踪分支可参加选择。原分支无合格波形时可采用合格跟踪分支；两者都合格时，主频差超过12bpm保留原分支，其余情况需要跟踪证据评分至少高15%才切换。评分结合原有共识、运动重叠和歧义程度，是工程指标，不是准确率概率。

选中窗口以原正Hann权重拼接真实波形，之后仍从保存波形重新估计局部频谱心率和离线DP心率。没有用参考心率选择分支，也没有用“延续上一心率”补齐空缺。

## 开发与验证

两个结构各测试0.10秒和0.15秒缺帧上限，分别对同设置V2.2比较。所有五段真人视频和一个合成控制完整保留。参考只用于事后评价，data1沿用原估计同步及全部七个时间偏移。细则见 evaluation_protocol.json；参数冻结和实际运行身份见 validation/protocol_before_validation.json。

此前已看过这些资料，所以本轮属于开发回归，不能称独立受试者泛化验证。重用经哈希及视频身份校验的V2.3配对增量，只节省未改动的光流计算；颜色校正、波形融合和心率都重新运行。安装后的原视频运行另行核验。

## 运行与新增输出

```bash
python analyze_motion_v2.py /absolute/path/video.avi \
  --pixel-mode tracking_screened --algorithm-mode guarded_fusion \
  --max-gap 0.10 --output /absolute/path/new_results
```

直接调用CLI仍保留legacy兼容模式，V2.4入口必须显式指定以上算法参数。

- frame_trace.csv：原baseline颜色、未校正V2.3颜色、新颜色、真实跟踪／回退来源、低频校正量。
- branch_routing.csv：每窗原版与跟踪分支提议、评分、真实跟踪比例、分支选择及原因。
- baseline_roi_waveforms.csv、两分支的proposal与waveform：用于审查选择依据。
- 原有波形、心率、融合诊断、summary和comparison图继续保留。所有未接受的最终fusion心率为空；不把诊断峰值当有效心率。

实验接入不自动替换原默认入口。只有预先固定的性能条件和安装核验满足后，才考虑正式升级。
