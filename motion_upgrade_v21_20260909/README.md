# rPPG V2.1：代码一致性修复

目标是在运动中保留可用的脉搏信号，并让报告的心率确实来自输出的波形。本版修复候选顺序依赖、心率与融合波形脱节、实际贡献区域的采样来源，以及拒判窗口仍导出谱峰的问题。

| 改动 | 作用 |
|---|---|
| 确定性候选分组 | 成员与加权中位数一致；改变候选遍历顺序或诊断编号不改变结果 |
| 从实际融合波形计算最终心率 | `spectral_peak_bpm` 为局部谱峰，`ridge_bpm` 为离线 DP；候选共识另存 |
| 记录实际贡献区域 | 只用 `waveform_weight>0` 的区域；观测标记取全部贡献的交集，插值标记取并集 |
| 明确拒判输出 | 最终融合 HR 在拒判时为 NaN；`raw_spectral_peak_bpm` 保留原始诊断峰 |
| 保留同输入对照 | POS/CHROM 的采样、滤波、心率算法和数值阈值沿用冻结版本 |

整条链路是离线处理：零相位滤波、相邻窗重叠融合和 DP 都可能使用未来信息。局部谱峰分支同样来自离线预处理信号。本版没有承诺实时延迟或波形形态恢复。

在 WSL 项目目录使用新入口，输出目录必须尚不存在：

```bash
cd '/home/fengbujue/项目/rppg识别'
./run_motion_v21.sh '/完整路径/人脸视频.avi' --output './results/新视频_v21'
```

有 UBFC 三行格式同步参考时，在命令后添加 `--reference-ubfc '/完整路径/ground_truth.txt'`。其他格式需要适配采样率、时间戳和同步关系，不能直接套用该参数。推理完成后才读取参考进行评分。

| 文件 | 内容 |
|---|---|
| `fusion_waveform.csv` | 实际融合信号 `base`；`covered/observed/interpolated` 采样来源 |
| `fusion_heart_rate.csv` | 最终局部谱峰和离线 DP 心率、拒判原因、对应提议信息 |
| `fusion_proposals.csv` | 区域共识候选及提议接受状态，不能直接作为最终 HR |
| `fusion_diagnostics.csv` | 每候选的区域、权重、提议接受状态、实际波形贡献 |
| `roi_waveforms.csv` | 额头、左右脸颊各自的 POS/CHROM 波形和插值标记 |
| `pos_* / chrom_*` | 保留的同输入基线对照；使用时仍需按 `accepted` 筛选 |
| `summary.json` | 输入身份、源码哈希、配置、覆盖率；有参考时另列误差 |

`waveform_generated` 表示该窗口自行生成了波形；`neighbor_covered` 表示没有自行生成、但被相邻窗口完整覆盖。两者都不代表心率一定准确。采样来源也不等于上游滤波的完整时间支持或生理置信度。

评价使用两个方面：心率的 MAE、RMSE、有效输出比例 C_out、有效输出内 ±5 bpm 命中率 P5、全部参考窗口内 ±5 bpm 成功率 R5；波形的参考基频 SNR。没有同步参考时，误差和参考 SNR 填 NA；波形相关系数及形态质量仍需合适的同步 PPG 参考与预先规定的对齐方法。

45 项代码测试、五个保留视频回归和五种固定 RGB 合成场景的结果保存在版本结果目录。UBFC 已用于问题诊断，复跑属于回归检查；新增数据应先冻结本版再独立评价。全区域共同扰动的合成场景仍可能全部拒判，不能把无输出解释成高精度。

今天新增的数据建议保留：原始人脸视频、同步 PPG/ECG/设备 HR 及各自时间戳、受试者和动作标签。先按受试者划分开发集与测试集，固定窗口、阈值及参考同步方式，再一起报告误差和覆盖率。仅有视频也可分析采样和输出，但不能计算真实心率精度。当前前端以恒定帧率建立时间轴，新增视频需检查是否为可变帧率。

WSL 部署保留原 `run.sh`、`run_motion_v2.sh` 及旧版本结果，新版通过 `run_motion_v21.sh` 明确调用。

原 Windows 审计工作区保留 `evaluate_v21.py`、`run_validation_v21.py`、首轮与最终回归资产。完整评估和实际候选夹具测试依赖该工作区中的旧版本证据；部署目录不能单独复现这部分历史对照。部署后可独立运行无外部夹具的前端、融合、CLI 和波形心率测试。
